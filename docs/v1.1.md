# IAF v1.1: what changed against v1.0, and the address migration guide

The reference version of the engine is **v1.1**. v1.1 is the official patch (`iaf-patch`, [formats/rtpatch.md](formats/rtpatch.md)).
The ported logic always follows v1.1. A user who has only the v1.0 files can still play: setup applies the patch when
it is available, otherwise the engine runs on v1.0 data (see [v1.0 data compatibility](#v10-data-compatibility)).
The other docs and the code cite **v1.1** addresses, rewritten from the
[address map](#address-map-for-everything-our-docs-cite) at the end of this file, which is kept for going back to
v1.0 (its "cited in" column lists where each address was cited before the rewrite).

How this was produced:

- Ghidra 12 headless analysis of the v1.1 `IAFJets.exe` (md5 `f16475359115e76def64b1b040b05a14`). Undiscovered
  code (vtable-only functions) was filled in on both versions, giving 14 600 functions in v1.0 and 14 741 in v1.1.
- Functions were matched by normalized instruction streams (image addresses masked), aligned in link order.
  Leftovers were paired through the call graph and references, then by global similarity.
- For every pair, all references were checked. Calls go to the matched callee. `.rdata` constants are compared by
  value (as float, string or pointer). `.data` globals are compared by their mapped address.
- Every changed function our docs or code cite was then read as a decompile diff and verified by hand.
- The outputs live in `assets/ghidra_v11/` (git-ignored). You can regenerate them with the scripts in
  `assets/ghidra_v11/work/` and `assets/ghidra_v11/scripts/`:
  - `map.tsv`: all functions.
  - `changed_all.tsv`: every changed function.
  - `cited_map.tsv`: the table at the end of this file.
  - `iafjets.c`: the v1.1 decompile.
  - `iafjets_v10_full.c`: the v1.0 decompile, including the filled-in functions.
  - `work/dc.py <v1.0 addr>`: a normalized decompile diff.

## Overview

| | count |
|---|---|
| functions, identical except relocations | 13 808 |
| only struct or stack offsets moved ("layout") | 188 |
| only a referenced constant, string or equivalent accessor differs | 117 |
| instruction stream differs | 269, mostly codegen (see below) |
| v1.0 functions without a counterpart / v1.1-only functions | 218 / 359 (mostly split, merged or inlined helpers) |

The patch build is a **full rebuild**. The source paths changed from `C:\BlueStar\Source\…` to `C:\IafPatch\…`, and
Tgen from `C:\Tgen\TgenIIs` to `C:\TgenIIStr`. Most "changed" functions are therefore compiler noise:
- register or FPU reordering;
- trivial accessors folded into other identical copies, such as the Rodrigues vector helpers, which v1.1 callers
  reach through `00459ac0`/`459b30`/`459b80`/`459ba0`;
- two grown classes.

The grown classes shift many offsets:

- **Cockpit renderer R**: +8 bytes from ≤0x1690 onward. For example, `R+0x20b8` (state pointer) is now `0x20c0`,
  `0x2718` is `0x2720`, and `0x2758` is `0x2760`. `0x5b0`–`0x5fc` do not move.
- **Cockpit state S**: 8 bytes inserted at `S+0x1c`, which now holds the projected FPM x,y as ints. Every field
  ≥0x1c moves +8, for example `S+0x38`→`0x40`, `0x48`→`0x50`, `0x13f4`→`0x13fc`, `0x1458`→`0x1460`.
- **Flight params P** (bd.ibx section, stride `0x17c`→`0x18c`): four new rudder keys at `P+0x16c..0x178`. The derived
  fields move up: `0x16c`→`0x17c`, and `0x170/174/178`→`0x180/184/188`.
- **Flight state S (β)**: `S+0x260..0x298` is now a second-order channel object (see F1).
- **Ejection thrower**: 0x18 → 0x34 bytes.
- **Global .data**: shifted by +0x4000 to +0x4c60 in steps. `.rdata` shifted by about +0x4000, but the float constant
  pool was re-laid out, so always use the map, not an offset.

## Changed ported systems in detail

### F1: sideslip β channel (rudder)

- **v1.0** (`5a78f0`): β was the ramp `S+0x280`. It moved toward β_cmd at `k·BetaRate`, clamped to ±MaxBeta. A separate
  HUD-only ramp at `S+0x260` held `k·w_z − β_cmd`, using the 3° constant `0x60de0c`.
- **v1.1** (`5aa700`): `S+0x260` is a channel object of the α class, laid out as follows.

| Offset | Field |
|---|---|
| `0x260` | t0 |
| `0x268` | pos |
| `0x26c` | rate |
| `0x270` | target rate |
| `0x274` | T |
| `0x278` | pos(T) |
| `0x27c` | accel |
| `0x280` | startAccel |
| `0x284` | stopAccel |
| `0x288` / `0x28c` | ∓Rmax |
| `0x290` | B |
| `0x294` | K |
| `0x298` | β_cmd |

Per call:

```
k = V < 400 ? max(V·slope + b, 0.25·BetaRate) / BetaRate : 1      (v1.0 threshold 375)
Rmax = BetaRate·k; startAccel = |RudderStartAccel·k|; stopAccel = |RudderStopAccel·k|
K = RudderK·k·(1.5 if |β_cmd| ≤ 0.1·MaxBeta); B = RudderBeta·k
err = wrap(β_cmd − pos); damp = B·rate·Rmax (×0.5 if |rate| > π)
r = clamp(err/π·K/Rmax − damp, −1, 1)·Rmax;  channel.step(now, fmod(pos), rate, r)
```

The following changed with it:
- pos is no longer clamped to ±MaxBeta;
- the HUD β channel and the 3° constant are gone;
- getter 8 (`5a64b0`) returns the physical β;
- on the ground, the 1 Hz update steps the channel with the stored gains instead of re-basing;
- placement resets it;
- state-set sets pos = 0;
- β samplers (`5aa520`, `5aa0b0`, `5b9250`, `5bb9f0`) use `fmod(pos)`.

The loader `5b2940` reads the new keys after AlphaBeta. They are stored raw (not converted from degrees); the
defaults are what the exe uses when a key is missing.

| Key | Offset | Default |
|---|---|---|
| RudderK | `P+0x16c` | 5.0 |
| RudderBeta | `P+0x170` | 0 |
| RudderStartAccel | `P+0x174` | 0.5 |
| RudderStopAccel | `P+0x178` | 0.5 |

bdgen values:

| RudderK | Aircraft |
|---|---|
| 7.5 | F-4, Mirage, Kfir, Lavi |
| 5.5 | F-15, F-16, MiG-29 |
| 6.25 | MiG-23 |

RudderBeta is 0 in every section, so the loop has no damping term. Check in the port whether it overshoots.

### F2: roll axis
The attitude in normal mode (`5b4840→5b9530`, vtable `0x60dee8→0x611db0`) still rotates the left-wing vector by dφ.
The axis is now row 1 of `Euler(S+0x14, S+0x18, wrap(S+0x1c))`, i.e. the body nose axis of the saved attitude. v1.0
used f = v/|v|. The α and β rotations still act on the velocity direction.

### F3: spin
`5a7d50→5aab90`:
- The recovery yaw target is `s1·π/2 + β·slope` with `slope = π/(2.2·MaxBeta)` (v1.0 1.8). MaxBeta is read from `P+0xb8`.
- In the stay branch, the X/Y/Z axes are re-based and keep their acceleration. Z is clamped by the new `5adae0`.
- The branch sets `veh+0xc3c = 1`.
- The 5 Hz tick (`5a4230`) now also runs β_cmd (`5b1840`, asym 0) and the β update while in spin.
- Entry and exit thresholds are unchanged.

### F4: ground roll / taxi
The only code change in `5b7a20→5bac40` is two constants:
- the AI wheel-brake factor 2→4 (`0x612474`);
- the rolling-drag multiplier above 1 m/s 0.7→0.8 (`0x612480`).

The taxi release-note item comes from the data (WheelsBrakeDragIndex):

| Aircraft | WheelsBrakeDragIndex |
|---|---|
| F-4 | 10000→5000 |
| F-15 | 15000→9000 |
| F-16 | 15000→7000 |
| Mirage | 8000→4500 |
| Kfir | 8000→4000 |
| MiG-23 | 15000→8000 |
| MiG-29 | 15000→7500 |
| Lavi | 15000→10000 |

With these values, static AB thrust / (μ·weight) goes from 0.42–0.72 to about 1.0–1.4 (MiG-23 0.79).

### Damage (docs/damage.md)
- **Blast formula `463660→4642f0`**: register reordering only. The skill-factor block at 4639a6–4639ec (v1.1
  `464636`…) still applies RookieDamagePercent / RegularDamagePercent to non-player-side targets, so **the "enemies
  tougher on easy levels" bug is still in v1.1**.
- **Falling-heading bug**: unchanged. The destruction motion `4966fe→4971ae` and `4970cc→497b7c` differ only by
  folded accessors.
- **`443fd0→443f60`**: an accessor inlined. It reads no skill value, so damage.md §4.1 and the front-end table are
  wrong to call it a skill reader. The skill reader in that path is `444140` (the AI fire decision above).
- **`44ca90→44d760`** (systems-damage codes): a refactor. The console texts are now CStrings read from `IAF.ibx`
  `[DamageLocalization]`, built by about 32 new init functions (`446ca0`–`447870`), with the v1.0 English texts as
  defaults. The switch logic is identical.
- **`4a8150→4a89d0`** (entering state 1): the single-player "own jet in cockpit view" branch is removed. That branch
  set model slot 8 (`*_BC`), `53e070(1)` and `obj[9]=0`. v1.1 always shows model [5] and clears the crew cockpit flag.
  This is part of the eject fix.
- **`4a8280→4a8ae0`**: multiplayer kill credit (above).

### Ejection (docs/part-animation.md)
- **Throwers**: 0x34-byte objects with this layout:

| Offset | Field |
|---|---|
| +4 | dir |
| +0x10 | offset |
| +0x1c | dist |
| +0x20 | crew |
| +0x24 | &pos |
| +0x28 | schedule |
| +0x2c | &flag |
| +0x30 | isSeat |

- At creation: dir = normalize(0,0,z0) rotated by −heading, offset = (−x0,−y0,0), dist = |z0|. They are scheduled at
  t0 / t0+Interval with a 0.05 s period.
- **Tick** (`53f460`, clone `53f890`) replaces v1.0 `53d910`: `dist += Speed; pos = (x0, y0, dist)`. It stops when
  dist > 100 (`0x60c6f8`).
- Compared with v1.0 (`pos.z += Speed; pos.y += 0.5·Speed`), the part now **rises straight up with no aft drift**.
  The constant 0.5 (`0x608828`) is gone.
- Speed (`0x65bc74→0x65ffdc`), the parachuter spawn (`546350/546b60 → 548400/548c10`) and the rotor 10° spin
  (`0x608808→0x60c6d0`) are unchanged.
- **Crew ctor** `53ea80` now initialises `crew+8 = 0`.
- **Cockpit flag**: the five `53e070` calls in the event dispatcher are gone. The own jet's draw in the cockpit pass
  (`4d9d70`, `4db9e0`) now sets the flag before drawing (via `4da060`) and restores it after (`4c3210`).

### HUD / cockpit (docs/cockpit.md, docs/mfd.md)
- **FPM / ladder**: see the summary table. Our `hud.gd` already projects the velocity vector for the FPM. That was our
  own deviation from v1.0 and is now the **original v1.1 behaviour**, so keep it and document it as v1.1. The v1.1
  pitch ladder is 12 px/deg (ui-scaled) from the projected FPM, offset by γ = (S+0xc − (S+0x40·R+0x272c +
  S+0x50·R+0x2730))·57.3 mod 5°, and rotated by roll.
- **Gun cross**: v1.0 and v1.1 both draw it at `MainOffsetY − GunRetPositionY + vpan`. Only the data changed, by
  −10 px (see the data section). `hud.gd` draws it at GunRetPositionY.
- Everything else in the cockpit and MFD modules (HUD modes, RWR drawer, TSD, horizon disc, MFD bars, map.emf, lights,
  cockpit.ibx reader) is layout-only. The RWR add/remove/visibility logic is byte-identical.

## Data files (v1.0 → v1.1)

- **`Resource\Md\*gen.skp`, `bdgen.dat`**: encrypted with `plain[i] = cipher[i] ^ ((0x67+i) & 0xFF)`.
  - v1.1 `FUN_004d44f0` (called from sim init `4b234f`) decrypts them into `MD\bd.ibx` and `MD\<id>.dat` before every
    flight, overwriting the plaintext files. The unchanged loaders then read those. If a file is missing the exe
    shows "Could not open flight model files".
  - All 15 `*gen.skp` decode byte-identical to the v1.0 `.dat` envelopes.
  - `bdgen.dat` is the new `bd.ibx`, 21169 → 21479 bytes. Its changes are:
    - SpeedBrakesDragIndex ×2 (F-4 300→600, F-15 243→500, F-16 275→550, Mirage 300→600, Kfir 310→620,
      MiG-23 225→450, MiG-29 227→450, Lavi 250→500);
    - WheelsBrakeDragIndex lowered (F4);
    - RudderK added to the 8 player jets (F1);
    - Lavi PlaneDragIndex and thrust;
    - C130 `AllowStall` 0→0.0 (unread);
    - `[Autopilot]` NoChangeRollCone 4.0→1.75, and SmallConeRollK 60 → SlowConeRollK 90 (the exe only ever read
      SlowConeRollK, default 90, so nothing changes).
  - Our `read_md` already reads the decrypted v1.1 files.
- **`msvcrt.dll`**: the VC5 runtime 5.00.7303, which the rebuilt exe links against. Not needed by us.
- **`cockpit.ibx`** (cfir, f15, f16, f4-2000, mirage): only `[HUD] GunRetPositionY` changes, lowered by 10 in each:

| Cockpit | GunRetPositionY |
|---|---|
| cfir | 170→160 |
| f15 | 170→160 |
